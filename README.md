# Static-Code-Analysis

## Project Overview
This repository contains a simple Python inventory management system that was analyzed and improved using static code analysis tools. The goal of the project is to demonstrate how tools such as Flake8, Pylint, and Bandit can help identify issues related to code style, maintainability, and security.

The project includes:
- an original version of the inventory script with several quality and security issues
- an updated version with improvements based on static analysis feedback
- analysis reports generated by the tools
- a short reflection summarizing the experience

## Purpose
The project was created to:
- practice static code analysis in Python
- identify and fix common coding issues
- improve code readability, safety, and maintainability
- understand how automated analysis tools support software quality

## Files in This Repository
- inventory_system.py: original version of the inventory management script
- inventory_system_updated.py: improved and refactored version
- inventory.json: sample inventory data file used by the script
- flake8_report_updated.txt: Flake8 analysis report for the updated code
- pylint_report_updated.txt: Pylint analysis report for the updated code
- bandit_report_updated.txt: Bandit security analysis report for the updated code
- reflection.md: personal reflection on the static analysis process
- README.md: project documentation

## Features of the Inventory System
The script provides basic inventory operations such as:
- adding items to stock
- removing items from stock
- checking current quantity
- loading and saving inventory data to JSON
- identifying low-stock items

## How to Run the Script
Make sure Python 3 is installed on your system.

Run the original version:
```bash
python inventory_system.py
```

Run the updated version:
```bash
python inventory_system_updated.py
```

## Example Output
The script prints:
- current stock for selected items
- a list of items below the low-stock threshold
- the saved inventory data

## Static Analysis Tools Used
### 1. Flake8
Flake8 was used to detect style and formatting issues such as:
- unused imports
- missing blank lines
- bare exception handling

### 2. Pylint
Pylint was used to assess code quality and readability. It reported issues such as:
- missing docstrings
- non-snake_case function names
- use of dangerous default values
- use of eval()
- missing encoding specification when opening files

### 3. Bandit
Bandit was used to detect security-related weaknesses. It reported:
- use of bare except
- unsafe use of eval()

## Key Improvements Made
The updated version improves the original script by:
- renaming functions to snake_case for Python style consistency
- adding docstrings for functions and the main block
- replacing dangerous default argument values with safer patterns
- using explicit encoding when opening files
- replacing bare except with specific exception handling
- removing the use of eval()
- improving file handling with proper context managers
- making the code more readable and easier to maintain

## Summary of the Analysis Results
The static analysis tools helped identify both minor and serious issues:
- some were simple style problems
- others pointed to real maintainability and security concerns
- the updated version shows a clear improvement in code quality and robustness

## Reflection Highlights
The project highlighted that:
- static analysis tools are valuable during both development and review
- small code issues can accumulate into larger maintainability problems
- security vulnerabilities such as eval() should be removed early
- automated checks improve collaboration and reduce future bugs

## Notes
This repository is intended as a learning example for static code analysis in Python and demonstrates how automated tools can be used to improve software quality.
